# 产品需求

## 背景与目标

作者持续积累作品，外部 Agent 的一次性输出难以保存依据、修订和审阅意见。固定专业结构使确定性解析、检查与渲染不必每轮重新生成，同时保留 Markdown、结构数据和自由文本。将固定故事组织成可检查、试玩、存档和交付的分支叙事工程。

## 用户旅程与首版范围

固定故事依据 → 组织节点与变量 → 检查分支 → 按路线试玩 → 保存和回放 → 离线HTML交付 → 把选中路线交给宿主候选任务。

首版专业对象为：节点、选项、类型化变量、条件、状态变化、结局、固定工程存档。所有管理动作可通过稳定 CLI/MCP 完成，GUI 用于阅读和审阅；不要求用户把对话内容重复填表。高级手动编辑保留。

## 成功标准

固定输入可回读，专业结果可解释，修改可比较，原操作可恢复，下游可接续。正确处理用例04中的失败和反例，与安装数量或动作数量分别评价。创作质量仍由作者判断。

## 边界

不持有第二份正式正文库，不内置 Agent、聊天或模型循环，不把推断当正式事实，不自动执行作者采纳、定稿或外部发布。
